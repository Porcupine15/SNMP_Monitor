# SNMP Monitor

Веб-приложение для домашнего мониторинга коммутаторов, маршрутизаторов и
принтеров по SNMP. Backend написан на FastAPI, данные хранятся в PostgreSQL,
интерфейс доступен на порту 8000.

Фронтенд расположен в `frontend/`: `index.html` содержит разметку,
`styles.css` — оформление, `app.js` — логику интерфейса. Файлы доступны через
`/static/` и не дублируются в backend.

## Быстрый старт

1. Скопируйте `.env.example` в `.env` и задайте надёжные значения для
   `DB_PASSWORD` и `SECRET_KEY`.
2. Запустите `docker compose up --build`.

Для постоянного запуска в Debian VM на Proxmox используйте отдельную
инструкцию [DEPLOYMENT.md](DEPLOYMENT.md) и файл `compose.production.yml`.
3. Откройте `http://localhost:8000`, зарегистрируйте первого пользователя и
   добавьте устройства через «Настройки» — вручную или поиском по своей подсети.

Для поиска используйте только свою подсеть, например `192.168.1.0/24`.
Один запуск ограничен 1024 адресами, чтобы не вызвать случайное сканирование
большой сети.

## Что уже работает

- JWT-авторизация и защищённые API;
- обнаружение доступных SNMP-устройств (v1/v2c);
- периодический ICMP-опрос и журнал смены статуса;
- таблица портов: состояние, скорость, PVID, количество и список FDB MAC,
  а также IP, сопоставленные с MAC через ARP;
- список принтеров и чтение уровня расходника, если устройство поддерживает
  стандартный Printer-MIB;
- серверный ping выбранного IP-адреса.
- обнаружение обычных клиентов домашней сети по ICMP/ARP;
- локальный LAN-агент для передачи MAC и имён из ARP-таблицы хоста;
- роли пользователей, аудит, история доступности и CSV-экспорт;
- настраиваемые интервалы опроса и параметры ping.

## Разработка без оборудования

В «Настройках» доступен demo-коммутатор. Он не обращается к сети и показывает
типичный снимок портов с PVID, MAC и ARP-IP. Проверки backend запускаются так:

```bash
docker compose exec -w /app -T backend pytest -q
```

Роли: первый зарегистрированный пользователь становится `admin`, остальные —
создаются администратором. Публичная регистрация после первого аккаунта
отключена; временно включить её можно через `ALLOW_PUBLIC_REGISTRATION=true`.
Добавлять устройства могут `admin` и `operator`.

## Клиенты локальной сети

Страница «Клиенты сети» сканирует подсеть без SNMP. Для получения MAC-адресов
из реальной LAN запустите агент на Mac/Linux-хосте, где работает Docker:

```bash
set -a
source .env
set +a
python3 agent/lan_agent.py
```

Агент использует отдельный `LAN_AGENT_TOKEN` и не требует пароль от роутера
или Wi-Fi. Клиент считается устаревшим, если не наблюдался более 10 минут.

## Миграции и реквизиты

Alembic-миграции находятся в `backend/alembic`. Для новой базы используйте
`alembic -c alembic.ini upgrade head` из каталога `backend`. В текущей базе
миграция ролей уже применена.

Укажите `CREDENTIALS_ENCRYPTION_KEY` в `.env` до ввода SNMP community или
паролей v3: новые реквизиты будут храниться в БД зашифрованными Fernet.
Сгенерировать ключ можно командой из `.env.example`.

## Важные ограничения

- Trunk/Access пока являются локальной меткой порта. Изменение конфигурации
  коммутатора через SNMP SET намеренно не включено до выбора модели устройства
  и проверки её OID в домашней сети.
- VLAN, ARP и тонер сильно зависят от производителя. Сейчас показывается
  стандартный PVID из Q-BRIDGE-MIB; tagged VLAN и vendor-specific данные будут
  добавлены профилями оборудования после получения моделей/OID.
- Новые SNMP-реквизиты шифруются Fernet перед сохранением в БД. Ключ
  `CREDENTIALS_ENCRYPTION_KEY` необходимо хранить вместе с резервной копией:
  без него расшифровать community и пароли SNMPv3 невозможно.
